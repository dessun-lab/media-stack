# Route model fit

## Establish task fit

Read the current task and [root instructions](../../../AGENTS.md). Assess the
hardest material requirement across investigation, authorized implementation,
validation, and handoff. For Media Stack, distinguish mechanical documentation
from uncertain network ownership, shared writable data, image provenance, and
Portainer lifecycle reasoning. A long prompt alone is not a reason to escalate.

Use Luis's explicit model/reasoning choice as the starting profile. Use exact
labels supplied by Luis or exposed by the current environment. Do not copy an
old selector/pricing matrix from another repository, invent API mappings, or
claim a hidden active model. A recommendation does not switch the session.

When choosing among known available profiles, prefer the lowest plausible one
that covers the entire task with reliable validation and acceptable rework.
Account for ambiguity and switching overhead, not just the easiest subtask or
an assumed token price. Do not obtain external benchmarks or credentials merely
to route ordinary work. If fresh product facts are necessary, use the applicable
official-documentation workflow and label availability/cost uncertainty.

Record one concise result, combined with the task's normal progress receipt:

```text
Model fit: <requested or recommended profile> / <reasoning>.
Basis: <hardest material requirement and why this profile fits>.
Mode: <direct work | bounded brief | assessment/proposal>.
```

Keep the result session-local unless a requested handoff needs it. For example,
an assessment of VPN dependencies, shared state, and deployment ownership can
justify retaining Luis's requested Astra / High through the whole assessment.
This example is a task-fit judgment, not a general capability or pricing table.

## Retain and reassess

Retain the profile across ordinary source reads, corrections, edits, and final
checks. Reassess only when a coherent task ends, a new material requirement
appears, or Luis declares a model gate. Avoid routing separately for every file.
Do not interrupt sufficient authorized work solely to suggest a cheaper profile.

At an ordinary boundary, continue if the current profile remains sufficient.
If a material requirement cannot be met, explain the specific gap and request
the needed model/reasoning change before dependent work. If Luis explicitly
requires a strict model-review stop, honor that exact boundary even when no
switch is recommended. A continuation inherits the current task's decision;
scoped gates expire at their named boundary and do not leak into unrelated work.

An explicit stop, effect boundary, or unresolved operational decision takes
precedence. Report coincident blockers/gates together. Routing never authorizes
deployment, secret access, new paid calls, or delegation.

## Planning fit

Use direct execution for small clear work. Use
[execute-orchestrated-brief](../execute-orchestrated-brief/SKILL.md) for an
authorized interdependent task. For unresolved stack ownership or migration
choices, produce a bounded proposal and stop before implementing those choices.
Do not install Spec Kit or another framework as a consequence of routing.

If selectable profiles or the active setting are unavailable, say what is
unknown and continue with task-fit reasoning when safe. Do not manufacture a
model gate merely because selector metadata is absent.
